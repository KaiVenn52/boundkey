Project description

AI agents need to buy metered APIs and data. Giving an agent a wallet key exposes more money than the task needs, while approving every small payment interrupts the work.

BoundKey lets the user approve a narrow payment permission on Android. The agent creates a disposable Ed25519 session key and sends a proof-bound request to the phone. The user reviews the service, recipient and maximum USDC spend before their existing wallet signs through Mobile Wallet Adapter.

The phone builds a Solana Payment Channel open transaction. The payer wallet stays on the phone, while the agent holds the session key used to sign cumulative MPP vouchers. The channel binds payments to its recipient and deposit. Request validation also checks that the amount and recipient shown on screen match the embedded payment challenge.

The Android application includes a safe offline demonstration for judges: three simulated API calls consume $0.035 of a $0.50 budget, then a $5 request and a changed recipient are blocked. This demonstration sends no transaction. The repository includes the real MWA signing path, a merchant service, the desktop session bridge, and 20 protocol and security tests.

BoundKey is a hackathon prototype for developers running agents that need metered payments. The next steps are persistent service hosting, stronger device pairing, transaction decoding and security review before any production custody use.

Judge setup

Install the APK on Android, open BoundKey and tap Run safe offline demo. No wallet or development server is required for this demonstration. Generate three calls, try the $5 attack, change the payee, and end the capability. Live testing uses a dedicated Devnet wallet and the instructions in the repository.
